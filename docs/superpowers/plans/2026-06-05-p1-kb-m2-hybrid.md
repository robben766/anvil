# KB-M2:混合检索(手写 BM25 + RRF)实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 自研稀疏检索全链路:jieba 分词 + 手写 BM25 倒排索引(PG 持久化)+ 手写 RRF 融合;排名敏感指标(MRR)+ 对抗 golden 用例证明 dense/sparse 互补;UI 检索调试视图展示三路过程;顺手清 M1b 后置项(error SSE/上传限制/CORS env)。

**关键认知(写进文章):** 基线 recall@5=1.0、precision@5=0.2 是单相关 chunk 语料在 k=5 下的数学上限——证明混合检索的价值必须换排名敏感指标(MRR/hit@1)并加"dense 弱势"对抗用例(精确术语/数字/产品代号查询),否则就是自欺。

**Tech:** jieba(纯 Python 分词,kb 新增依赖)/ BM25 Okapi(k1=1.5, b=0.75)/ RRF(k=60)。

---

### Task H1: 手写 BM25 SparseIndex(PG 持久化,TDD 手算锁定)

**Files:** Create `packages/kb/src/anvil_kb/store/bm25.py`、`packages/kb/alembic/versions/0002_bm25_postings.py`;Modify `packages/kb/pyproject.toml`(+jieba>=0.42);Test `packages/kb/tests/test_bm25.py`

- 迁移 0002:`kb_postings(term text, chunk_id uuid FK kb_chunks ondelete CASCADE, tf int, PRIMARY KEY(term, chunk_id))` + `ix_kb_postings_term`;`kb_chunks` 加列 `token_count int NOT NULL server_default '0'`
- `tokenize(text) -> list[str]`:jieba.cut_for_search,过滤纯空白/标点(保留数字与字母 token,统一 lower)
- `PgBM25Index(session_factory)` 实现 `SparseIndex` 协议:
  - `index_chunks(chunks)`:分词 → 计 tf → 批量插 postings + 更新 token_count(与所属 doc 的向量写入同事务边界外亦可,幂等靠 upsert 时先删旧 doc 级联)
  - `search(query, k)`:query 分词 → 取这些 term 的 postings → Python 算 BM25(N=chunk 总数,df=term 的 posting 数,avgdl=token_count 均值)→ top-k ScoredChunk(score=BM25 分,越大越相关)
- **手算锁定测试**:3 个微型 chunk、给定分词结果,纸面算出 BM25 分数(k1=1.5,b=0.75,idf 用 `ln((N-df+0.5)/(df+0.5)+1)` Okapi+1 平滑)精确断言(误差 1e-6);另测:查询词全不在库 → [];中文+数字混合("90天")可检索;删除文档级联清 postings

### Task H2: ingest 双写 + RRF 融合 + Retriever 编排

**Files:** Modify `packages/kb/src/anvil_kb/ingest/pipeline.py`(可选参数 `sparse_index=None`,给了就双写)、`packages/kb/src/anvil_kb/retrieve/retriever.py`;Create `packages/kb/src/anvil_kb/retrieve/fusion.py`;Test `packages/kb/tests/test_fusion.py`、test_pipeline 补双写用例

- `fusion.py`:`rrf_fuse(ranked_lists: list[list[ScoredChunk]], k: int = 60, top: int = 5) -> list[ScoredChunk]`——按 chunk_id 聚合 `Σ 1/(k+rank)`(rank 1-based),融合分写入 score,稳定排序(分同则按首次出现);**手算锁定**(两路各 3 条、有交集,纸面算 RRF 分断言)
- `Retriever` 增加 `mode: Literal["dense","sparse","hybrid"]="hybrid"` 与 `sparse_index` 注入;hybrid:两路各取 `k*4` 候选 → rrf_fuse 取 k;dense/sparse 单路保持原语义;返回前附 `debug` 可选数据(见 H4)
- pipeline 双写测试:假 sparse(记录调用)断言 index_chunks 收到与 store 相同的 chunks
