# KB-M3:cross-encoder rerank 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 接入 cross-encoder 重排(fastembed `BAAI/bge-reranker-base`,本地),打通 hybrid→rerank 链路;用 MRR + 延迟双指标实证"双塔 vs 交叉编码"的精度/成本权衡;核心实验问题:**rerank 能否救回 kb-16(三模式都低的换述难例)?**

**Architecture:** 重排是检索编排的最后一级:hybrid RRF 融合出 top-N 候选(N=k*4 已有)→ cross-encoder 对 (question, chunk) 逐对打分 → 取 top-k。Reranker 协议化(可换实现);真模型测试标 `live`(模型 ~1GB,CI 不下载),单元测试用假 reranker。

Retriever:构造参数 +`reranker: Reranker | None = None`。语义:reranker 非 None 时,hybrid/dense/sparse 的候选阶段照旧,但**最终排序前**把候选(hybrid=RRF 全量融合列表,即 top=k*4 内的融合结果;dense/sparse=各自 k*4 候选)交给 reranker 取 top-k;retrieve_debug 的 `reranked` 字段记录重排后 k 条(无 reranker 时 None,fused 仍是最终结果)。**注意 retrieve() 与 retrieve_debug() 仍共享单次检索实现。**

测试(全假 reranker,真模型不进默认测试):假 reranker 反转输入序→断言 retrieve 最终序被重排、debug.reranked 记录、无 reranker 行为零变化;FastEmbedReranker 的真模型测试写一个标 `@pytest.mark.live` 的(断言中文相关对 > 无关对)。
